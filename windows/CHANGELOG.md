### 用户体验评审修复批次（2026-10-11）

来源是一轮对 `windows/` 的全量代码评审（发现清单见 [`REVIEW_UX_2026-10-11.md`](REVIEW_UX_2026-10-11.md)），
按其第一批 + 第二批实施 15 项。设计与取舍见 `DESIGN.md` §25。**本批首次在真实 Windows 机器上完成
`dotnet build`（0 错误）与 `dotnet test`（475 项：473 过 / 2 跳过 / 0 失败——含此前在 macOS 主机上
无法运行的 8 个 STA 测试）；涉及热键、剪贴板、气泡通知与浮窗观感的行为仍未做真机手工验证（步骤见 DESIGN §25.4）。**

稳健（防丢结果）：

- 终稿看门狗按音频时长缩放（`max(30s, 时长×5)`，上限 5 分钟）：慢机器上两分钟长听写的整段重跑
  会超过此前固定 30 秒的看门狗，结果是整段内容以「识别超时」丢失。超时路径同时把已识别的预览文本
  兜底复制到剪贴板；等引擎加载的轮询上限从 20s 放宽到 60s（冷盘首次加载不再误报超时）。
- 首启引导被 × 关闭累计三次后不再自动弹出（托盘菜单「使用引导…」仍可随时打开）：
  此前习惯性点 × 的用户每次开机都会被弹窗骚扰。

反馈：

- 模型下载完成 / 自动重试放弃时发托盘气泡通知（失败气泡可点击打开设置页）；
  此前下载完成只有托盘图标变色，用户在别的窗口里毫不知情。
- 录音阶段引擎仍在加载时，浮窗状态行显示「录音中 · 模型加载中…」（攒满 1 秒音频才提示，
  与松键后的「正在加载识别模型…」同一对信号）；此前这段时间预览一直空白、无从分辨原因。
- 识别 / 输入超过 2 秒后，状态行追加等待秒数（「识别中 · 5s」）：长听写整段重跑要等十几秒，
  递进的数字是「还在算」的唯一信号。
- 插入阶段（等修饰键松开或剪贴板备份，最长 5 秒）浮窗显示「正在输入…」而不是继续「识别中」。
- 纠错成功后、上屏前把纠错后的文本经预览通道顶上浮窗：插入被推迟或降级为复制时，
  用户第一次有机会校对「纠错改了什么」（此前只能看到 ASR 原文）。
- 下载自动重试等待期按热键，提示改为「将在 N 秒后自动重试（第 x/3 次）」而不是「模型还没下载」。

界面：

- 引导页重排改为可见性 diff + SuspendLayout：下载进度每 200ms 刷一次时不再「全部隐藏再逐个显示」，
  消除闪烁风险；不可见时只更新模型不重排。
- 下载期间托盘菜单 / tooltip 与设置页按钮只在值变化时赋值；隐藏状态的设置窗不再全量刷新。
- 麦克风测试被听写等强制停止时，状态行显示原因（如「已开始听写，测试已停止」）而不是空白。
- 设置页麦克风下拉展开时重新枚举设备：插拔麦克风后不必关窗重开。

性能：

- 预览窗口自校准让位：有活跃会话时推迟到 SessionEnded 后再跑，两遍合成基准推理（1–3 秒）
  不再插在「引擎刚加载完就按热键」的用户的第一次预览 / 终稿前面；引擎被换掉时作废推迟的校准。
- LLM 能力缓存内存化（此前每次纠错都读一次文件，且发生在 UI 线程同步段）。
- 浮窗电平去掉第二重 30ms 节流（音频线程已节流过），波形有效帧率恢复设计值。

### 跟嘴 · 跟手 · 稳健：体验优化批次（2026-10-09）

方案、取舍与真机验证步骤见 `DESIGN.md` §23。**在 macOS 主机交叉编译（win-x64 / win-arm64，0 警告）并跑单测（共 438 项：
429 过 / 1 跳过 / 8 失败；失败的 8 项仍是需要 WinForms STA 线程的 `SetupFormTests` ×5 与 `HudCornerStrategyTests` ×3，改动前后一致）；
以下全部 Windows 行为（钩子线程、卡键看门狗、EcoQoS、剪贴板、浮窗）均未在真机验证。**

识别 / 性能：

- 预览改为事件驱动：采集块 600 ms → 200 ms；自上次预览累计 ≥ 300 ms 新音频且含语音时就开始，而不是固定 600 ms 一次；
  推理线程占空比 ≤ 2/3。说话到出字的延迟预期明显缩短（**未实测**）。
- 松键时中止仍在跑的预览（ORT `RunOptions.Terminate`），终稿不必排在它后面；排队中尚未开始的预览直接作废。
- 预览窗口按耗时预算校准（`0.3 s ÷ RTF`，限 6–15 秒），校准跑两次取第二次；此前按 RTF 分 15/10/6 三档。
- 进程级退出 EcoQoS 执行速度节流，避免 Win11 把后台托盘进程放到能效核。

稳健：

- 剪贴板备份不再在 UI 线程上等待（此前最多阻塞 1.5 秒，期间全局键盘钩子被一起卡住）：备份没读完时插入按 25 ms 轮询重试，
  最多 5 秒，超时不碰用户剪贴板，提示从托盘「复制上一次识别结果」找回。
- 低级键盘 / 鼠标钩子移到专用线程（自带消息循环）；健康检查与新增的卡键看门狗也在该线程上。
- 按住模式卡键看门狗：UAC / Ctrl+Alt+Del / Win+L 等切到安全桌面后收不到松键事件时，约 0.5 秒内按松键处理（此前录到 120 秒上限才结束）。

界面：

- 浮窗：纠错中提示「再按 X 跳过」；录音剩 15 秒时状态行倒计时；预览里刚变化的尾部更暗、约 0.3 秒后变亮；
  不透明度 < 100% 时淡入淡出（约 0.1 秒）；点击穿透（同样仅不透明度 < 100% 时有效）。
- 设置页改浮窗位置 / 不透明度时弹出约 2 秒的示例浮窗；「诊断与帮助」新增最近 20 次听写的耗时与「复制诊断信息」（不含识别文本）。
- 耗时摘要新增 `final_wait`、`backup_wait`、`preview_avg`、`preview_abort`、`tail_speech`、`qos`（含义见 DESIGN §23.5）。

没做（见 DESIGN §23.2 / §23.4）：停顿处提前定稿分段、松键后补录、连续听写保持麦克风、逐像素半透明、麦克风测试、引导页改版、
锁屏 / 睡眠恢复；切换模式的「再按 X 结束」提示、浮窗高度平滑过渡、错误提示点击打开设置页。

### 体验与性能优化批次（2026-10-09）

来自一轮对 `windows/` 的代码审查（挑选其中的 10 项）。设计与取舍见 `DESIGN.md` §22。**在 macOS 主机交叉编译（0 警告）并跑
单测（共 407 项：398 过 / 1 跳过 / 8 失败；失败的 8 项是需要 WinForms STA 线程的 `SetupFormTests` ×5 与
`HudCornerStrategyTests` ×3，在 macOS 上本就无法运行，改动前后一致）；以下全部 Windows 行为均未在真机验证。**

- 剪贴板备份挪出 UI 线程：识别阶段在后台 STA 线程先备份好用户的剪贴板，插入时只核对剪贴板序列号（期间用户复制了
  新内容则作废、退回同步备份）。此前备份在 UI 线程上逐格式读取，Excel / Word 这类延迟渲染的大块选区可能要数百毫秒，
  同在 UI 线程的全局键盘钩子也被卡住。
- 发布启用 ReadyToRun：减少登录后首次听写前的 JIT。macOS 主机交叉发布实测目录 +2.6 MB（x64）/ +3.3 MB（arm64），
  ZIP 约 +1.1 MB；**启动收益未实测**。
- 智能纠错连接预热：开始录音时向纠错服务发一个不带密钥、不带文本的 `HEAD /`（30 秒内至多一次），说话期间完成
  DNS / TCP / TLS，识别完成后的纠错请求复用该连接。
- 浮窗字体与设置窗口统一（中文界面用微软雅黑 UI）；此前浮窗写死 Segoe UI，中文靠系统回落字体。
- 托盘菜单新增「复制上一次识别结果」：粘贴按键发出去不代表目标应用真的收下了文字，这是找回结果的最后一道手段。
  结果只保存在内存里（不落盘、不进日志），听写进行中拒绝复制。无论随后是粘贴成功还是退化为只复制都会记录。
- 录制热键时，若录到 Ctrl+C / V / X / Z / Y / A / S、Ctrl+Space、Alt+F4 / Tab / Space、Shift+Space、Win+Space
  这类系统、输入法或通用编辑的常用快捷键，会提示它在其他应用里将被拦截（只提醒，不禁止）。
- 浮窗「跟随光标」优先落在正在输入的文字插入点旁（`GetGUIThreadInfo`），取不到时仍用鼠标位置。Chrome / Electron /
  UWP 等自绘输入框不上报系统插入符，行为与之前相同。
- 麦克风探测改为按设置里选定的输入设备进行（此前恒按「自动」），保存了不同的输入设备后会自动重新探测一次。
- 日志目录从漫游的 `%APPDATA%\VoiceTyper\logs` 改为本机的 `%LOCALAPPDATA%\VoiceTyper\logs`（旧目录里的历史日志不会
  自动迁移或删除，可手动清理）。
- `app.manifest` 的版本号 3.5.0.0 → 3.5.1.0；「麦克风启动中」阶段画面静止，不再以每秒 30 帧重绘。

### Win11 真机 HUD 空白透明（2026-10-09）

紧接上批：麦克风修好后，同机按热键 HUD 只剩一个空白透明的框 + 顶部一条细黑线，内容全都不见；
Win10 正常。分析与修复见 `DESIGN.md` §21：

- **根因**：HUD 用 `Form.Opacity`（分层窗口 + `SetLayeredWindowAttributes`）做整窗半透明，而句柄
  创建时无条件启用了 Win11 的 DWM 圆角（`DWMWA_WINDOW_CORNER_PREFERENCE`）——DWM 对这类分层窗口
  改走「自管理形状」合成路径后客户区不再绘制，只补出一条 1px 顶线。Win10 上该调用本就失败回退
  Region 裁剪，因此表现正常。
- **修复**：分层窗口改为显式 `DWMWCP_DONOTROUND` + 去掉 DWM 1px 边框，回到与 Win10 一致的
  Region 圆角 + 自绘边框；不透明度 100%（非分层）时仍用 DWM 圆角。透明度实时调整会正确切换两侧。
- 新增 STA 单测 `HudCornerStrategyTests`（分层走 Region、两种圆角互斥、切换换边），本机 Win10
  全量 384 项：382 过 / 2 跳过。**Win11 真机验证步骤见 DESIGN.md §21.4。**

### Win11 真机麦克风打开失败（2026-10-09）

来自一台 Win11 真机的反馈：设置页报「麦克风设备打开失败：可能被其他应用独占，或驱动异常」，热键只有
HUD 外框、麦克风未打开，其他应用录音正常。分析与修复见 `DESIGN.md` §20：

- **多声道麦克风阵列支持**：Win11 麦克风阵列的共享模式混音格式可能是 4 声道，此前采集链路对 >2 声道
  直接抛异常（正是这条横幅的来源之一）。新增按帧平均下混，3 声道及以上不再拒绝设备。
- **失败可诊断**：麦克风探测失败现在会以 Error 级写入完整异常（含 HRESULT 十六进制），
  设置页横幅与引导页会把真实原因拼在猜测文案后；日志位于 `%APPDATA%\VoiceTyper\logs\app.log`。
- 单测新增 3/4 声道的流式重采样对比与按帧平均用例（共 381 项：379 过 / 2 跳过）。
  **真实 4 声道设备上的录音效果尚未真机验证。**

### 交互与性能修正（2026-10-09）

来自一轮对 `windows/` 的代码审查。**在 macOS 主机交叉编译并跑通单测（共 375 项，其中 5 项 `SetupFormTests`
需要 WinForms STA 线程，在 macOS 上本就无法运行，改动前后一致）；窗口、托盘、热键、剪贴板、DPI 相关改动均未在
Windows 真机验证。**

交互：

- 识别完成时 Alt / Shift / Win 仍被按住（例如 Ctrl+Shift+空格，识别很快、手还没离开）：不再立刻降级成
  「只复制到剪贴板」，而是最多等约 0.4 秒让修饰键松开再粘贴；等待期间用户开始了下一段听写或控制器被停止，
  结果改为复制到剪贴板，不丢。耗时摘要新增 `mod_wait`。
- 物理 Ctrl 仍按住时（热键含 Ctrl）粘贴只发 V 的按下 / 抬起，不再注入 Ctrl 的抬起，避免目标应用误以为
  Ctrl 已松开。
- 等智能纠错时再按一次热键：放弃等待、直接插入识别原文并提示（耗时摘要 `llm_result=skipped`），
  不再是「上一段听写尚未完成」。
- 空闲卸载后的冷恢复：松键后若模型还要加载超过约 0.3 秒，浮窗显示「正在加载识别模型…」，加载完成后恢复「识别中」。
- 浮窗不透明度允许 10%–100%（此前设置页可选 10%–39%，浮窗实际被夹到 40%，设置无效）。
- 托盘图标：空闲时是应用图标；其余状态在应用图标右下角叠状态点（此前第一次状态变化后整个换成自绘的浅色麦克风，
  浅色任务栏上几乎看不见）。托盘菜单的「开机自启」勾选在每次展开菜单时重新读取，不再与设置页不一致。
- 设置窗口在显示前按所在屏幕的可用区域收紧（1920×1080、125% 缩放这类常见笔记本上，原先 1080×800 的设计尺寸
  放大后会超出可用区域）。
- 设置页「模型目录」显示模型实际所在目录（可能来自 ModelScope 缓存或手动指定的 `model_dir`），不再一律显示下载目录。
- 引导已完成的用户不再在每次开机时探测麦克风（会让任务栏的麦克风使用指示闪一下）；打开设置页或引导页时按需探测。
- 界面字体按语言选择（中文雅黑 UI、英文 Segoe UI），并共享实例；引导页文本区按文本高度自适应，英文文案不再被固定高度截断。

性能：

- 特征链：fbank 不再整段复制一份放大 32768 倍的波形；LFR 与 CMVN 合并为一次写入扁平缓冲区，省掉每帧各两次数组分配
  和一次整体拷贝（与两步实现逐位一致，新增对照测试）。
- 会话缓冲区初始预留从 120 秒（约 7.7MB）改为 30 秒，超过后按倍数扩容。
- 模型下载进度回调只按时间节流（每 200ms 一次），不再在快网络下每秒刷新几十次界面。
- 设置页脏检查不再每次按键重复序列化已载入的配置。

### 按热键到可开口的延迟（2026-10-09）

真机日志显示按下热键到麦克风打开要 0.41–0.54 秒（距上次录音不到约 9 秒）或 0.92–1.18 秒（超过约 15 秒），
期间 UI 线程被同步阻塞，浮窗要等麦克风打开后才出现。分析与数据见 [DESIGN.md §18](DESIGN.md#18-2026-10-09-按热键到可开口的延迟)。

### 修复：此前的工程根本编不过

- `AudioChunker` 在 C# 14 下无法编译（first-class span 让 `MemoryMarshal.Cast(byte[])` 选中了只读重载，
  之后对结果赋值报 CS8331）。顺带把逐样本入队出队的 `Queue<float>` 换成定长线性缓冲（VW-17）。
- `FbankParityTests` 用了 xunit v3 才有的 `Assert.SkipWhen`；改为 `Xunit.SkippableFact`，缺模型时明确显示「已跳过」。
- `LlmCorrector` 在调用前不检查已取消的令牌，取消测试因此不成立。

### 修复：会影响正式使用的缺陷

- **界面语言保存后重启又变回中文**：`ConfigStore` 手写的 YAML 序列化漏写了 `ui.interface_language`。
- **`hotkey.mode` 等新字段不会丢**：设置页保存热键时不再用一个全新的 `HotkeyConfig` 覆盖掉触发方式。
- **录音默认走「通信设备」端点**：蓝牙耳机连接时它几乎总是指向「免提通话」端点，一打开麦克风就把耳机切到电话音质。
  改为默认设备，并新增输入设备策略（见下）。
- **门禁不能吞掉进行中的听写**：空闲卸载后首次按热键会触发模型加载，协调器随后置上「未就绪」门禁；
  如果门禁也拦截松键 / 切换模式的第二次按键，录音就停不下来。门禁只拦「新开一段听写」。
- **下载失败反复抢焦点**：自动重试的每次失败都会把设置窗口弹到最前面；改为同一段未就绪期内只做一次。
- **预览在静音段白耗 CPU**、**录音期间扩容 memcpy**、**控制器状态机无法单测**（VW-10 / VW-17 / VW-24）。

### 新增（对齐 macOS）

- **首启四步引导**（欢迎 → 麦克风 → 语音模型 → 试一试）。最后一步在引导窗口自己的输入框里跑一次真实听写，
  区分「没采到声音 / 采到但识别为空 / 插入失败 / 未就绪」。完成记录存 `%LOCALAPPDATA%\VoiceTyper\onboarding.txt`，
  托盘菜单「使用引导...」可再次打开。
- **触发方式** `hotkey.mode`：`hold`（默认）/ `toggle`。刻意不做「短按 toggle、长按 hold」的自动判别。
- **单独修饰键热键**：`hotkey.key: right_ctrl`。干净单击才触发；按住期间出现任何其他键、修饰键或鼠标按下
  （Ctrl+点击、Ctrl+滚轮）即作废并静默丢弃本次录音。只支持右 Ctrl——Alt / Win / Shift 的单击在 Windows 上本身有
  系统副作用，而低级钩子无法吞掉修饰键事件。此类热键下浮窗延迟 150ms 出现。
- **设置页「录制热键」**：直接按下想用的组合，录制期间暂停全局热键监听，避免录到的是「触发了一次听写」。
- **未就绪门禁**：模型下载中 / 加载中 / 加载失败时热键照常监听，按下会用 HUD 说明缺什么（缺模型时把设置窗口摆出来，
  5 秒节流）。此前这几种状态下钩子根本没装，按热键与「应用已崩溃」完全一致（VW-01）。
- **Esc 取消识别阶段**：录音中与识别中都可取消；识别中取消不会中断已在跑的那次推理，只丢弃它的结果。
  无听写进行时 Esc 照常传给前台应用。
- **HUD**：实时电平波形、状态行显示输入设备名、最多两行的尾部预览（放不下时以省略号开头）、
  「纠错中…」阶段、录音 1.5s / 4.5s 仍无声音时的提示、识别为空时的明确说明、按屏幕 DPI 缩放（VW-14）、
  「减少动态效果」（系统动画关闭）时不做呼吸 / 脉冲。
- **浮窗位置** `ui.hud_position`：`bottom_center`（默认，此前是屏幕顶部）/ `bottom_right` / `near_cursor` / `hidden`。
  `hidden` 只静音过程，错误与「没有识别到内容」仍会浮出来。
- **输入设备策略** `audio.input_device`：`auto`（默认）/ `system` / 端点 ID（设置页可手选）。`auto` 仅在默认输入与默认播放
  都是蓝牙时改用内置麦克风。端点分类依据 `PKEY_Device_EnumeratorName` + 名称关键字，**分类是否可靠需真机核对**；
  每次录音的耗时日志会记录分类结果（枚举值，不含设备名）。
- **`asr.preload_on_launch`**（默认 `true`）：关闭时启动只确认模型文件在不在，首次按热键才加载，且与录音并行。
- **模型下载**：≥ 32MB 的文件四段并行（`Range: bytes=0-0` 探测总长，各段独立 `.segN` 文件，续传只看文件长度），
  任何异常永久回落单连接；单连接路径处理 `416`；失败按 5s / 20s / 60s 自动退避重试，手动重试重置计数，
  取消下载同时取消待触发的重试。
- **LLM 关闭深度思考**：请求默认带 `thinking: {"type": "disabled"}`；服务以 400 / 422 且响应体提到 `thinking` 拒绝时，
  去掉字段重发一次，并按「地址 + 模型」缓存结果（`%LOCALAPPDATA%\VoiceTyper\llm_capabilities.txt`，不含 API Key）。
  「测试纠错」总是重新探测并显示结果。
- **会话级耗时日志**：每次听写输出一行 `metrics` 摘要，只含数字与枚举；`DictationMetricsTests` 用反射钉死
  「不存在 string 类型成员」。
- **检查更新**：托盘菜单手动触发，只读 GitHub Releases 的 `latest`，不做后台联网。
- **预览静音跳过**、`RecognitionBuffer` 预留单段上限容量。
- 版本号与 macOS 对齐为 3.5.0；发布启用 ReadyToRun（VW-20）。

## 真机验证清单

在真实 Windows 10 / 11（x64，有条件再验 arm64）上逐项确认。凡是与下列条目相关的结论，
都必须区分「代码审查通过」与「真机验证通过」。

**安装与首启**

1. 安装包安装 / 卸载（per-user，无 UAC）；卸载后开机自启项是否清掉；SmartScreen 提示。
2. 首次启动弹出四步引导；托盘图标是否可见（Windows 11 默认收进「^」）；关闭引导后再启动会再次出现，走完后不再出现。
3. 引导「试一试」：在引导窗口输入框里完整跑通一次听写。

**热键**

4. `Ctrl+F2` 按住 / 松开；目标应用**收不到** F2；松开修饰键先于主键的顺序；Esc 取消（录音中 / 识别中）。
5. 切换模式：第二次按键结束；录音期间 Esc 取消；识别中再按热键提示「上一段听写尚未完成」。
6. 右 Ctrl：单击触发；`Ctrl` + 点击 / 滚轮 / 其他键作废且不留下浮窗残影；150ms 延迟是否足够。
7. 设置页「录制热键」：录制期间按当前热键不会触发听写；录完自动恢复监听。
8. 长时间运行（≥ 数小时）后热键是否仍有效；日志里是否出现钩子重装。

**麦克风**

9. 默认设备录音；拔麦克风后新会话能否恢复；多声道 / 麦克风阵列设备。
10. 蓝牙耳机（AirPods 等）：默认输入与输出都是蓝牙时是否改用了内置麦克风，日志 `input=` 是否为 `builtin*`；
    输出不是蓝牙时是否尊重蓝牙输入；手选设备是否生效。**端点分类（BTHENUM / USB / HDAUDIO 与名称回退）的准确度需要在这里核对。**
11. 录音期间静音麦克风：1.5s 后是否提示「没有检测到声音」。

**浮窗**

12. 不抢焦点（在记事本里录音，光标与输入焦点不变）；三种位置；多显示器（听写目标在哪块屏 HUD 就在哪块屏）。
