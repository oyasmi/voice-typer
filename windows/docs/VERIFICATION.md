## 1. 通用手工验收矩阵（总纲）

覆盖一轮完整验收需要触达的全部范围，出自第一轮评审（WR 计划 §6），历轮沿用：

| 范围 | 必测场景 | 验收重点 |
| --- | --- | --- |
| 首次启动 | 新测试用户，无 SDK/模型；断网、取消、恢复 | 可见进度和故障原因；应用内完成第一次输入 |
| 麦克风 | 内置、USB、蓝牙；无设备、禁用权限、切默认设备 | 选中源正确；实际电平；失败可解释 |
| 按键 | 左右修饰键、不同松键顺序、Esc、重复按键、AltGr/IME | 不触发目标快捷键；不产生卡键/重复会话 |
| 常规输入 | 记事本、浏览器、Office、聊天工具、VS Code、终端 | 文本完整，原剪贴板尽可能恢复 |
| 插入边界 | 管理员窗口、切应用、同窗口换输入框、粘贴不支持 | 不误插入；结果可恢复；不虚报复制成功 |
| 剪贴板 | 文本、图片、文件、HTML/RTF、占用、期间再次复制 | 原内容恢复或明确降级，不覆盖新复制 |
| 生命周期 | 空闲十分钟、睡眠/锁屏恢复、拔麦、重载、退出 | 引擎可恢复，无旧结果迟到插入 |
| 桌面与安装 | 多用户/RDP、二次启动、自启、升级、卸载 | 实例范围正确，系统状态与 UI 一致 |
| 显示 | 多屏、100/150/200% DPI、字体缩放、高对比度 | 无遮挡/裁切，不抢输入焦点，恢复操作可达 |
| 性能 | 短句及 30/60/120 秒音频，冷/热/空闲恢复，电池模式 | 记录实际延迟和资源，分清测量与估算 |

补充（历轮新增的重点场景）：中文 IME 与 AltGr 下的热键行为、右 Ctrl 单独修饰键 + 鼠标/滚轮、
锁屏/睡眠唤醒后立即按热键（钩子主动重装）、快速 Esc 取消后立即重按 ×20、多声道麦克风阵列
（Win11 Intel Smart Sound 4 声道，见 DESIGN §20）。

### 2.2 3.5.0 功能对齐的逐项清单（原 CHANGELOG「真机验证清单」）

在真实 Windows 10 / 11（x64，有条件再验 arm64）上逐项确认。

**安装与首启**

1. 安装包安装 / 卸载（per-user，无 UAC）；卸载后开机自启项是否清掉；SmartScreen 提示。
2. 首次启动弹出四步引导；托盘图标是否可见（Windows 11 默认收进「^」）；关闭引导后再启动会再次出现，走完后不再出现。
3. 引导「试一试」：在引导窗口输入框里完整跑通一次听写。

**热键**

4. 组合键热键（如 `Ctrl+F2`）按住 / 松开；目标应用**收不到** F2；松开修饰键先于主键的顺序；Esc 取消（录音中 / 识别中）。
5. 切换模式：第二次按键结束；录音期间 Esc 取消；识别中再按热键提示「上一段听写尚未完成」。
6. 右 Ctrl：单击触发；`Ctrl` + 点击 / 滚轮 / 其他键作废且不留下浮窗残影；150ms 延迟是否足够。
7. 设置页「录制热键」：录制期间按当前热键不会触发听写；录完自动恢复监听。
8. 长时间运行（≥ 数小时）后热键是否仍有效；日志里是否出现钩子重装。

**麦克风**

9. 默认设备录音；拔麦克风后新会话能否恢复；多声道 / 麦克风阵列设备。
10. 蓝牙耳机（AirPods 等）：默认输入与输出都是蓝牙时是否改用了内置麦克风，日志 `input=` 是否为 `builtin*`；
    输出不是蓝牙时是否尊重蓝牙输入；手选设备是否生效。**端点分类（BTHENUM / USB / HDAUDIO 与名称回退）的准确度需要在这里核对。**
11. 录音期间静音麦克风：1.5s 后是否提示「没有检测到声音」。

**浮窗**

12. 不抢焦点（在记事本里录音，光标与输入焦点不变）；三种位置；多显示器（听写目标在哪块屏 HUD 就在哪块屏）。
13. 125% / 150% / 200% 缩放，以及在不同缩放的显示器之间移动，尺寸与文字是否正确。
14. Windows 10（Region 圆角）与 Windows 11（DWM 圆角）观感；透明度滑杆；「减少动画」开关。
15. 波形随音量起伏、三行尾部预览换行是否正确（中英混排：英文单词不被拆开、行首没有空格与逗号，见 DESIGN §28.3）；
    宽度 400 → 600 只跳一次、不回缩，超出三行整行滚动（DESIGN §29.2）。

**文本插入**

16. 记事本、Word、浏览器输入框、VS Code、Windows Terminal、cmd、PowerShell、以及**以管理员运行**的窗口
    （应提示 UIPI 并把结果留在剪贴板）；输入法组字中的行为；密码框。
17. 原剪贴板（文本 / 图片 / 文件列表 / Excel 区域）是否被恢复；连续两次听写不丢用户最初的剪贴板内容；
    带延迟渲染的大内容（如大范围 Excel）备份是否造成卡顿。

**模型与下载**

18. 真实 ModelScope 下载：四段并行是否被 OSS 接受 `Range`（`206` + `Content-Range`）；下载速度对比单连接；
    断网 → 自动重试 → 恢复；取消后再点续传；校验失败路径。
19. 关闭「启动时预加载」后首次按热键的体验（加载与录音并行）；空闲卸载后恢复。

**LLM 与更新**

20. 分别对「接受 / 拒绝 `thinking` 字段」的服务点「测试纠错」；日志 `llm_retry=` 与缓存文件；Key 存取（DPAPI）。
21. 「检查更新」：有网 / 无网 / 已是最新。

**性能**

22. 冷启动到可用的时间（ReadyToRun 是否生效）；识别 RTF、预览稳态 CPU（静音跳过是否生效）、常驻内存（预期约 500MB）、
    空闲卸载后的工作集；`allow_spinning` 等 ORT 线程选项的取舍（`DESIGN.md` §4.2）。

## 3. 性能测量方法

> 以下全部是**建议验收目标与方法，不是实测结果**（出自第三轮评审 §7）。先固定变量再建基线：
> 模型/ORT/线程数、Release 构建、硬件/电源模式/设备/DPI、是否开 LLM。温启动与空闲卸载后的
> 冷恢复分别测；记录 p50/p95、样本量和异常次数；冷启动分离文件缓存影响。

| 项目 | 方法 | 建议验收目标（非实测） |
| --- | --- | --- |
| 空闲资源 | 无窗/设置隐藏，分别引擎常驻与卸载，连续记录 CPU、唤醒、线程、句柄、Private Bytes、Working Set | 无麦克风采集、无持续推理；稳定空闲平均 CPU 可先以 <0.5% 为目标，注明采样口径 |
| 热键到反馈 | 原始钩子时间 → HUD 首次呈现（§18.3 的 `key_lag`/`dispatch`/`hud_shown`）；右 Ctrl 150ms 延迟单独统计 | 普通组合热键 warm p95 <100ms；右 Ctrl 按既定延迟验收 |
| 热键到首帧 | 钩子事件 → 实际第一缓冲；内置/USB/蓝牙分别测 | 内置/USB warm p95 <200ms 作为起始目标；慢设备建立独立基线 |
| 松键到输入入队 | 1/5/15/30/60/120s，LLM off；分阶段打点 | 同机较基线改善，且各时长不超过看门狗（`clamp(时长×5, 30s, 300s)`）；不承诺所有硬件统一绝对值 |
| 冷恢复 | 卸载后短句立即松手、长句、重复取消 | 不丢开头，不假 Ready；模型加载与录音并行，记录额外 final 等待 |
| 分配/峰值 | 每阶段 allocated bytes、LOH、Gen2 次数，ORT 前后 Private Bytes | 减少可解释的分配；正确性和首帧不回退 |
| 设置响应 | 打开、切页、字段输入、状态刷新，长文本/错误/高 DPI | 无同步设备枚举导致的长停顿；输入和焦点稳定，所有编辑器可达 |

内存口径：Private Bytes/提交内存判断仍持有的内存，Working Set 观察驻留，**二者同时看**。
不要在强制 GC 或工作集修剪后仅截任务管理器声称泄漏解决。初次 ORT arena 扩张允许形成新平台，
真正要检查的是同类后续循环是否持续增长。

### 3.1 稳定性验收矩阵

| 场景 | 重复/持续方式 | 通过条件 |
| --- | --- | --- |
| 短句/误触/取消混合 | 1000 次不同长度，夹杂 hold/toggle、右 Ctrl 手势 | 会话/线程/句柄趋势稳定，无旧音频污染，无重复上屏 |
| 常驻使用 | 至少 24h，发布前补 72h，周期输入与长空闲交替 | 不出现永久死键/卡状态；日志总量有界；资源无单调增长趋势 |
| 空闲卸载 | 1 分钟配置加速测试，另测用户真实时间配置 | 临界点开始会话不误卸载，恢复可识别，租约归零才释放 |
| 设备/电源 | USB 拔插、蓝牙断连/切端点、睡眠/恢复、锁屏/解锁 | 明确结束受影响会话，下一次可重建，资源各释放一次 |
| 模型异常 | 首启无模型、加载失败、文件损坏、重复重载 | 不留已完成「在飞」任务，不反复自激加载，恢复后的模型可用 |
| 推理阻塞 | 用假引擎控制不返回/超时；真实长音频另测 | 不宣称恢复但继续无限接单，不并发 Dispose 使用中的引擎 |
| 剪贴板/输入 | 图片/HTML/RTF/空内容/用户新复制/连续听写/管理员窗口 | 尽力恢复原内容、不覆盖新复制；失败提示准确，不静默丢结果 |
| 设置 | 草稿关闭重开、非法值、保存失败、外部自启变更、测试期间改字段 | 草稿保留、规范化一致，部分成功可理解，拒绝操作不改变会话阶段 |
| DPI/界面 | 中英文、不同缩放/双屏、窄工作区、高对比度/键盘 | 内容和操作可达，HUD 位置正确、不抢焦点，错误可阅读 |
| 退出 | 录音/模型加载/预览/final/LLM/下载/探测中退出 | 不使用已释放队列/控件，不残留后台采集或迟到插入 |

## 4. 待采集数据与决策阈值

对应 [REVIEW_HISTORY.md](REVIEW_HISTORY.md) §3 L1「待真机数据决策」项。**先采数据、后判定，
agent 不得自行判定「已满足/未满足」用户使用类的条件**：

| 数据项 | 采集方法 | 判定阈值 → 动作 |
| --- | --- | --- |
| 热键线程独立性（WT-07/T3-2） | `[metrics]` 日志的 capture 段耗时，≥50 次听写覆盖内置麦/USB/蓝牙；另看「热键监听已失效」自愈日志 | capture start p95 >150ms、出现过自愈日志、或用户反馈全局按键卡顿，任一成立 → 实施独立钩子线程（STA 专用线程 + 钩子线程拥有状态机 + 真机验收 IME/AltGr/右 Ctrl/睡眠恢复） |
| 重采样音质（WT-13/T3-1） | 跑 `ResamplerStreamingTests`，严格模式设 `VOICETYPER_RESAMPLER_STRICT=1` | SNR ≥40dB 且样本数偏差 <1% → 不改实现、DESIGN 记录结论关闭；否则改 `WdlResampler` 输入驱动 |
| 麦克风两档延迟（§18.1/§18.6） | 按 §18.5 采集 `queue/resolve/activate/init` 分段 | `init` 占大头 → 评估预初始化 IAudioClient（先确认不点亮任务栏麦克风指示，macOS 曾因此否决 pre-roll）；`key_lag`/`dispatch` 大 → UI 线程另有阻塞源 |
| A5 分段定稿 | 真机采集 >12s 与 >60s 听写的 `release_to_done` 分布 | 普遍 1s 内 → 不值得做；普遍明显 >1s → 与 macOS 一起评估管线改动 |
| A6 补录 | `tail_speech=1` 的比例 | 比例高 → 做（几十行，代价松键→上屏 +150ms） |
| A7 保持麦克风 | 真机确认两档延迟真实存在 | 产品接受指示灯多亮 ~20s 才做 |
| ORT 内存池/EcoQoS | 长听写前后 Private Bytes 对比、后台/前台推理耗时对比 | 有可观回收且推理不回退 → 评估 arena 配置 |

## 5. 验证记录写法

每批验证完成后，在 `windows/DESIGN.md` 对应批次节（或新开节）分三栏记录：

| 项 | 状态 |
| --- | --- |
